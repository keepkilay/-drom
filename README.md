# labsu.farpost — выгрузка каталога на Farpost / Drom

Модуль **1C-Bitrix** для формирования YML/XML-фида товаров из инфоблока каталога и публикации на:

Доработка Модуля поддерживает дедупликацию товаров по связке **OEM + производитель**, пошаговую генерацию XML, работу через cron/агенты Bitrix и использование в Docker-окружении.

---

## Требования

Для работы модуля необходимы:

* **1C-Bitrix**
* модули Bitrix:

  * `iblock`
  * `catalog`
  * `currency`
  * `sale`
* PHP с поддержкой запуска cron/агентов Bitrix
* каталог товаров с торговыми предложениями **SKU**
* Docker-окружение Bitrix с контейнером **cron**

---

## Как работает модуль

### Общая схема

```text
Админка модуля
ls_farpost.php
        ↓
Сохранение настроек
admin/system.json
        ↓
Запуск выгрузки / расписание
LSFarpostAddAgentExport()
        ↓
Пошаговая генерация XML
LSFarpostExport()
        ↓
Готовый фид
/farpost/export.xml
или
/farpost/export_{profile}.xml
        ↓
Farpost / Drom забирают фид по URL
```

## Пошаговый экспорт

Выгрузка выполняется в несколько шагов, чтобы не превышать лимиты PHP и cron.

### Этапы выгрузки

| Шаг | Действие                                                                  |
| --: | ------------------------------------------------------------------------- |
|   1 | Создание временного файла, запись заголовка YML, категорий и блока `shop` |
|   2 | Пакетная выборка товаров и запись тегов `<offer>`                         |
|   3 | Закрытие XML, перенос результата в `/farpost/export.xml`, сброс состояния |

Размер пакета товаров задаётся настройкой `gNumber`.

Состояние процесса хранится в файле:

```text
admin/system.json
```

Основные служебные поля состояния:

```text
start
step
gID
loaded
```

---

## Агенты Bitrix

| Агент                       | Назначение                        |
| --------------------------- | --------------------------------- |
| `LSFarpostAddAgentExport()` | Запускает выгрузку по расписанию  |
| `LSFarpostExport()`         | Выполняет пошаговую генерацию XML |

`LSFarpostExport()` выполняет отдельные шаги выгрузки с интервалом около 10 секунд.

## Результат выгрузки

Основной фид:

```text
https://ваш-сайт/farpost/export.xml
```

Фиды дополнительных профилей:

```text
/farpost/export_{код_профиля}.xml
```

Также доступен скрипт скачивания через директорию:

```text
/farpost/
```

Скрипт устанавливается из директории `install`.

## Настройки в админке

Модуль позволяет настраивать:

* инфоблок каталога — источник товаров;
* разделы — все или выбранные;
* тип цены;
* источник картинок:

  * `PREVIEW_PICTURE`
  * `DETAIL_PICTURE`
  * свойство типа «Файл», например `PROP:PHOTOS`;
* свойства товара и SKU;
* выгрузку свойств в XML как:

  * `<param>`
  * `<vendor>`;
* объединение SKU в один `offer`;
* фильтрацию по складам и остаткам;
* профили выгрузки;
* расписание ежедневного автозапуска.

# Кастомизации для transopt.net

Версия модуля содержит доработки под проект **transopt.net**.

---

## 1. Дедупликация по OEM + производитель

Дедупликация реализована в классе:

```text
lib/DedupFilter.php
```

Класс:

```text
LSFarpostDedup
```

Логика работы:

* формируется ключ из значений свойств:

  * `OEM`
  * `CML2_MANUFACTURER`
* если товар с такой связкой уже был выгружен, повторный товар пропускается;
* состояние дедупликации хранится в файле:

```text
/farpost/.dedup_oem_manufacturer.json
```

Это нужно, чтобы Farpost / Drom не получали дубли одной и той же запчасти из разных карточек товара.

---

## 2. Цена без скидок пользователя

Для получения цены используется функция:

```text
getFinalPriceInCurrency()
```

Она получает базовую цену из выбранного типа цен каталога без персональных скидок Bitrix.

Это важно для корректной работы в cron/агентах, где нет авторизованного пользователя и пользовательского контекста.

Дополнительно поддерживается применение процента из настроек профиля:

```text
lsFarpostApplyProfilePriceDiscount
```

---

## 3. Полный прогон за один запуск агента

Агент:

```text
LSFarpostAddAgentExport()
```

может выполнять до **500 шагов** `LSFarpostExport()` подряд.

Это нужно для больших каталогов, потому что cron, запускающийся раз в минуту, может не успевать обработать весь каталог стандартным пошаговым способом.

---

## 4. Блокировка параллельного экспорта

Для защиты от двойного запуска используются флаги в `system.json`:

```text
export_started
export_started_at
```

Логика:

* если экспорт уже запущен, повторный запуск блокируется;
* таймаут блокировки — **30 минут**;
* если процесс завис, после таймаута новый запуск сможет продолжиться.

---

## 5. Картинки из свойств инфоблока

Настройка:

```text
LSFarpostPictureType
```

позволяет выбирать источник изображений:

* `PREVIEW_PICTURE`
* `DETAIL_PICTURE`
* свойство типа «Файл»

Для проекта `transopt.net` используется вариант:

```text
PROP:PHOTOS
```

---

## 6. Защита от пустой выгрузки

Если в процессе экспорта не было выгружено ни одного товара:

```text
loaded = 0
```

готовый файл:

```text
/farpost/export.xml
```

не перезаписывается.

Это защищает рабочий фид от случайной замены на пустой XML.

## Cron

В Docker-окружении Bitrix экспорт запускается через контейнер `cron`.

Обычно cron вызывает стандартный механизм агентов Bitrix, а модуль уже через агенты запускает выгрузку по расписанию.

Основной агент автозапуска:

```text
LSFarpostAddAgentExport()
```

Пошаговый агент экспорта:

```text
LSFarpostExport()
```

---

## Особенности работы с большими каталогами

Для больших каталогов важно:

* использовать пакетную обработку товаров;
* не запускать несколько экспортов параллельно;
* не перезаписывать рабочий XML пустым файлом;
* хранить состояние выгрузки между шагами;
* учитывать ограничения cron и времени выполнения PHP.

В текущей версии эти механизмы уже предусмотрены.

## Итог

Модуль `labsu.farpost` формирует YML/XML-фид каталога Bitrix для Farpost / Drom, поддерживает профили выгрузки, работу через cron/агенты и содержит доработки для проекта `transopt.net`.

Ключевые доработки:

* дедупликация по `OEM + CML2_MANUFACTURER`;
* корректная цена без пользовательских скидок (выбор типа цены);
* поддержка картинок из свойств инфоблока;
* защита от параллельных запусков;
* защита от пустой выгрузки;
* ускоренный полный прогон через агент.
